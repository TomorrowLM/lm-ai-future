# 任务拓扑编排中台技术方案

## 目标与范围

将现有固定流程运行面板扩展为拓扑会话工作台：用户可以浏览已有拓扑会话、新建拓扑、从模板或空白画布开始配置，在保存后启动关联的 DSH 主会话。每条拓扑会话使用独立 JSON 文件保存拓扑配置及其全部节点执行状态。

本阶段仅定义前端和插件接口方案，不承诺实现完整 DAG 调度、跨 DSH 版本兼容、运行中恢复或保证恰好执行一次。

## 页面与交互

1. **拓扑会话列表**：显示名称、状态、最近更新时间、绑定的 DSH 会话 ID；提供打开、继续配置、新建入口。空状态引导创建。
2. **新建拓扑会话**：选择“使用模板”或“自定义节点”。模板初期提供“页面开发工作流”，并允许进入画布后编辑。
3. **流程画布**：复用当前拓扑原型的数据模型与交互，支持节点增删改、前置依赖、执行会话归属、Hook 配置和状态文件地址。顶部展示当前拓扑状态、JSON 路径及“启动”按钮。
4. **启动确认**：校验根节点目标、节点和依赖关系、文件路径、DSH 会话绑定。JSON 已存在时读取并校验归属，不静默覆盖。
5. **执行状态**：画布节点显示待运行、运行中、成功、失败、等待人工确认等状态；从该拓扑自己的 JSON 刷新状态。

## 页面组件与职责

- `TopologyList`：拓扑会话列表、空状态、创建入口。
- `CreateTopologyDialog`：模板与自定义模式选择。
- `TopologyCanvas`：画布、连线、节点选择和顶部状态栏。
- `NodeEditor`：单节点配置和校验。
- `RunStatusPanel`：运行信息、错误、人工确认动作。
- `topology-store`：列表/当前拓扑草稿、JSON 持久化调用和运行状态刷新。
- `dsh-orchestrator-api`：封装读取、保存、启动、状态查询、人工确认接口。

实现沿用当前 React 客户端入口 `src/client.ts`；Host 路由和运行逻辑分别位于 `src/host.ts`、`src/orchestrator.ts`。现有独立 `index.html` 作为交互参考，不直接作为运行中的页面实现。

## 数据模型与文件约定

每个拓扑会话有一个用户可配置的 JSON 文件。文件至少包含：

- `schemaVersion`、`topologyId`、名称、创建/更新时间。
- `sessionId`：绑定的 DSH 主会话 ID；首次启动且为空时创建 DSH 会话，成功后立即写回。
- `definition.nodes`：节点定义，包括类型、说明、执行会话、依赖、Hook 和结果输出配置。
- `run`：本次运行 ID、整体阶段、各节点状态、开始/结束时间、错误和结果地址。

拓扑定义与运行状态放在同一份 JSON 中，节点结果可内嵌或按节点配置写入外部结果文件；本期保留用户已要求的可定制结果配置。写入采用临时文件再替换，并对 schema 版本和 `topologyId` 做校验；启动已有文件时不覆盖未知或不匹配的数据。

## DSH 调用与状态流

1. 打开拓扑时读取其 JSON；没有文件时视为未保存草稿。
2. 点击启动后先写入“启动中”并校验。
3. 有 `sessionId` 时复用；没有时调用 DSH Session Controller 的 `create`，将返回 ID 写入 JSON。
4. 通过 Session Controller 的 `prompt` 把根节点目标提交给该主会话，再将拓扑状态置为运行中。
5. 节点完成判断和后继调度由中控读取/更新同一 JSON，根据所有前置依赖节点成功状态决定可运行节点；失败、取消、等待人工确认分别进入明确状态。

本机安装的 DSH `0.2.2-rc.3` 类型声明包含 `SessionController.create(SessionCreateRequest)` 和 `SessionController.prompt(SessionPromptRequest)`。但当前插件只接入 `agents`、`subagents`，尚未证实从 Web 侧栏到这些 Remote API 的完整调用路径及其权限/请求格式。Phase 4 开始前必须用该 DSH 版本实现一次接口探针并验证创建/提交；若插件环境不能调用，则需调整为 Host Remote API 路由，不能静默退化为仅更新 UI。

## 页面状态与错误处理

- 列表：加载中、空列表、读取失败。
- 新建：模板加载、模板缺失、草稿尚未保存。
- 画布：未配置、可启动、校验失败、启动中、运行中、人工确认、成功、失败、已取消。
- 持久化：无权限、目录不存在、JSON 损坏、schema 不兼容、同一拓扑并发写入。
- DSH：创建会话失败、会话不可用、prompt 被拒绝/排队失败、远端超时。

状态文件写入失败时停止后续调度，并向用户显示错误；不能显示为已成功。启动重复点击需由 `runId`/运行锁防止同一拓扑并发启动。

## 页面开发工作流模板

模板使用技能文档中的阶段名与职责，形成默认顺序依赖：

1. 需求分析：澄清目标、范围、验收条件，输出需求规格。
2. 技术方案：确定页面结构、数据/API 与技术决策，输出方案。
3. 实现计划：拆分任务、依赖和验证方式，输出执行计划。
4. 编码实现：按批准计划实现功能并记录变更。
5. 测试验收：运行项目验证、手动检查交互并记录结果。
6. 收尾交付：汇总产物、验证和遗留项。

模板节点是可编辑的流程定义；页面工作流技能自身 Phase 1/2/3/5 的用户确认门禁仍由使用该技能的执行过程遵循，不由插件自动替代或绕过。

## 验收标准

- 初次进入能看到拓扑会话列表与创建入口；支持模板/空白两条新建路径。
- 页面开发工作流模板包含六个阶段，依赖顺序正确，节点可编辑。
- 画布顶部有启动按钮和 JSON 地址；保存后重开能恢复该拓扑配置。
- 每个拓扑独立 JSON 包含绑定 DSH sessionId 和其节点运行状态；新建会话 ID 仅在创建成功后持久化。
- 启动校验失败、DSH 调用失败或 JSON 写入失败时，不会误报成功或调度后继节点。
- 组件行为、Host 路由和状态转换均有自动化测试；安装后的 DSH 面板通过真实浏览器完成一次不依赖模型计费的加载/保存 smoke check，并在可用测试会话下验证启动调用链。

## 已知限制与 Phase 4 前置核实

- Remote Session API 是本机 `0.2.2-rc.3` 类型声明证据；插件调用权限和具体 `ctx.remote` 使用入口仍需对照实际 Cordis 插件 API 验证。
- 当前执行引擎仍是固定子代理切片；完整 DAG 调度、Goal 完成判定、恢复/重试策略不在本方案直接假设为现成能力。
- 需定义拓扑 JSON 的路径选择 UI 和目录创建权限，方案暂按用户指定绝对路径处理。
