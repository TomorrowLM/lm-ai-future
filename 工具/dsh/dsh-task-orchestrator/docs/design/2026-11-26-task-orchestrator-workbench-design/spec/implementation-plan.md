# 实现计划：任务拓扑编排工作台

## 背景与目标

将 DSH 插件从固定的“主会话 → 子代理 → 人工确认”面板扩展为拓扑会话工作台。用户可以查看拓扑会话列表、新建模板或自定义拓扑、在画布编辑节点，并启动对应 DSH 主会话。每条拓扑会话使用独立 JSON 持久化拓扑定义、绑定的 DSH sessionId 和节点运行状态。

## 输入资料

- 技术方案：`../index.md`
- 当前 React 客户端：`src/client.ts`
- 当前 Host 路由：`src/host.ts`
- 当前运行状态机：`src/orchestrator.ts`
- 拓扑原型：`index.html`
- DSH 运行依赖：本机 `@deepseek-ai/dsh` `0.2.2-rc.3` 类型声明及实际 Cordis/Remote API 接入方式

## 任务边界

允许修改：`src/client.ts`、`src/host.ts`、`src/orchestrator.ts`、新增 `src/` 内职责清晰的类型/存储模块、`test/`、`README.md`、`scripts/build.mjs`（仅当构建入口需要调整）。

允许新增：拓扑工作台 React 模块、拓扑数据类型/模板常量、每条拓扑会话的 JSON 存储模块及相关测试。

不修改：DSH 安装目录、用户日常 Profile、与本需求无关的 `index.html` 既有交互；不安装到日常 Profile，不启动会调用付费模型的真实任务。

## 实现步骤（串行）

1. **DSH Session API 探针**：确认插件 Host/Web 侧的远端调用入口；为 `SessionController.create`、`prompt` 编写窄适配层或明确可调用接口；以 stub 测试验证输入/输出和失败处理。若调用入口不可用，停止在此步骤并报告，不伪造成功路径。
2. **拓扑 JSON 契约与存储**：定义 schema、模板与运行状态类型；实现按每条拓扑独立路径读取/写入、版本校验、原子替换、损坏/冲突处理；为文件存储建立测试。
3. **Host 编排接口**：提供拓扑列表/读取/保存/启动/运行状态接口；启动时复用已有 sessionId，无 ID 时调用 DSH 创建会话并先持久化；提交根节点任务后状态更新；失败时记录错误且不推进后继节点。保持当前子代理/人工确认切片可用或迁移行为有覆盖测试。
4. **React 工作台**：将客户端入口改为会话列表；实现新增入口及“页面开发工作流模板/自定义节点”选择；实现画布打开与节点配置；顶部展示 JSON 地址、运行状态和启动按钮；接入 Host 接口、加载/空态/错误态和校验反馈。
5. **模板与交互验收**：默认模板含需求分析、技术方案、实现计划、编码实现、测试验收、收尾交付六节点和顺序依赖；验证模板可编辑、保存并重开恢复；验证路径和依赖校验。
6. **整体验证与文档**：运行项目已有 build/test；修复回归；更新 README 的现状、接口和限制；完成隔离 DSH 中不触发模型的面板加载与保存 smoke check。任何真实模型调用都不在本次自动验证范围内。

## 串并行安排

- 全部串行，不并行修改。
- 步骤 1 决定 DSH 启动 API；步骤 2 固化 JSON 契约；步骤 3 和 4 都依赖前两项；步骤 5 依赖 UI/持久化完成；步骤 6 最后进行。
- 不并行原因：前端、存储和 Host 共享拓扑 schema、路由契约及状态枚举；并行会造成同一契约冲突。

## 合流检查点

- 步骤 1：确认实际插件可调用 DSH create/prompt，不仅有类型声明；若不可调用，暂停后续启动链路。
- 步骤 2：校验每个拓扑 JSON 独立、schemaVersion 和 sessionId 字段稳定，读取旧有运行 JSON 不会误覆盖。
- 步骤 3：接口请求/响应、状态转换、创建会话后的写回顺序有测试覆盖。
- 步骤 4：列表 → 新建 → 模板/自定义 → 编辑 → 保存 → 启动流程贯通；现有侧栏构建兼容。
- 步骤 6：测试命令输出、构建产物、隔离 DSH 加载结果和未覆盖项均记录。

## 验收标准

- 可查看多个拓扑会话；每条拓扑绑定独立 JSON 文件。
- 新建可选页面开发工作流模板或自定义模式；模板六阶段顺序正确且可编辑。
- JSON 保存并重开可恢复拓扑节点、依赖和 sessionId。
- 启动有 sessionId 时复用；无 sessionId 时创建 DSH 会话，创建成功后写回该拓扑 JSON，再提交主会话任务。
- API 或持久化失败显示错误，不将状态标记为成功，不推进后继节点。
- 自动化测试与构建通过；隔离 DSH UI 可加载并完成无模型调用的保存 smoke check。

## 执行方式

当前会话内顺序执行，不委派子代理、不使用并行任务。执行方式以用户选择方案 A 和要求直接执行为依据。
